## Instructor's 3-day prep cycle

1. Read the chapter.
2. Create the week's quiz + 10 homework problems, and work the homework by hand.
3. Refine the lecture notes, then build the week's content in Newton (quiz, homework, lecture
   notes and textbook reading excerpt posted to the module).

Step 3 is where this repo comes in: the quiz document goes in `source/phy215/quizzes/`, the
homework problem screenshots and answer key in `source/phy215/hw/HWn/`, and they get authored into
`physics2.js` + `_answerKeys.js`.

## Per-assignment notes

### ✅ q1 — "Quiz 1: Welcome & Course Survey"
Four questions, none graded on correctness: three `survey` questions (what interests you / what
can I do to make the course enjoyable / highest math class completed) and one `yesNo` (lab manual
purchased) carrying custom `yesReply`/`noReply` about the bookstore. **Both question types were
added to the engine for this quiz** — before it, a free-response question always went to Claude as
a physics tutor that graded correctness and asked Socratic follow-ups, which is wrong for an
opinion question, and `yesNo` had the textbook-access reply hardcoded.

### ✅ q2 — "Quiz 2: Electric Charge"
Two multiple-choice questions on the two-sphere demo (one negatively charged, one neutral):
before contact → **A, attract** (the charged sphere polarizes the neutral one, and the induced
opposite charge is nearer); after contact → **B, repel** (the conductors share the excess charge,
so both are negative). **The `choices` question type was added to the engine for this quiz** —
graded deterministically, with an authored misconception nudge per wrong option and a retry.

### ✅ hw1 — "Homework 1: Electric Charge & Electric Field"
10 Y&F Ch. 21 problems (21.2, 21.9, 21.22, 21.30, 21.33, 21.34, 21.45, an instructor-authored
**Clock** problem, 21.73, 21.87) — 31 gradable items. Figures `figE21-30.png` (square of charges) /
`figE21-33.png` (parallel plates) / `figP21-73.png` (ball on a string), copied straight from the
screenshots — figure-only, no caption to crop. The Clock problem is handwritten prose in the
source, retyped as the prompt with no figure.

**Parts a plain numeric does not serve, and why:**

- **21.30 is split `vector` + `math`.** The magnitude is an *expression* in $q$ and $a$
  ($\sqrt2 q/\pi\epsilon_0a^2$), so it is `math`; Claude accepts the equivalent $k$-form
  $2\sqrt2 kq/a^2$. The direction is a genuine diagram question, so it is a `vector` part — one
  arrow, direction-only (no `magTol`), `hideTicks`, graded instantly by `gradeVectors`.
- **21.34 is three `math` parts** — the problem explicitly asks for unit-vector form. Verified
  that Claude accepts component reordering and equivalent notation.
- **21.87(a)/(b) are `math`** — symbolic results in $m_p, v_0, \alpha, e, E$. Verified that the
  $2\sin\alpha\cos\alpha$ form of (b) is accepted and that dropping the factor of 2 in (a) is
  correctly rejected.
- **21.87(d) is a `graph`** — "Sketch the trajectory". Key: a concave-up parabola through
  $(0,0) \to (1.4466, -0.4176) \to (2.8931, 0)$, each point verified to lie on the true
  trajectory. Tolerance ±0.080 m, so a flat line (0.418 m off) fails.
- **⚠️ 21.87's parts are reordered** to (a) $h_{max}$ → (b) $d$ → (c) numerical values →
  (d) sketch. The textbook asks for the sketch before the numbers, but `GraphField` needs numeric
  axes, so the student must have the values first. Derive → evaluate → draw. The prompt says so.
- **21.45 uses signed $x$-components rather than magnitude + direction** — every field and force
  in that problem lies on the $x$-axis, so one signed value carries both facts. The stem states
  the convention. Six clean numerics instead of twelve blanks.
- **21.22 and 21.73 keep the established magnitude + `text` direction split**, since those
  directions need justifying (21.73 especially — the ball's charge is *negative*, so $\vec E$
  points opposite the force, back toward the wall).
- **The Clock problem asks for the time *and* a one-sentence justification.** "3:30" alone is the
  literal answer, but the content is the pairing/symmetry argument, so the reference requires it.
- **Nothing in this set is ill-conditioned** — no near-zero answers, no hypersensitive roundings,
  so no analogue of PHY 115's 3.54(b).

**Scientific notation.** This is the first set whose answers are mostly exponential, which
exposed that `toSigFigString` deliberately never emits sci-notation — 1.25×10¹⁹ rendered as
`12500000000000000000`. Answer-key entries now take an opt-in `sci: true`, used on 21.2(b),
21.45(b) i–iii and 21.73(a). Where a metric prefix reads more naturally the answer is expressed in
that unit instead (μC, μN, μm), which keeps most of the set free of exponents.

## Modules — hand-built, so `MODULES_PHYSICS2` stays empty

The live PHY 215 class's 17 modules were built **by hand** in the instructor Modules editor. The
seed template is only copied into a class's RTDB `modules` node when that node is **absent**
(`App.jsx` ~line 396), so for this class the template can never apply. Populating
`MODULES_PHYSICS2` would therefore have no effect while silently diverging from what students
actually see — so it is deliberately left `[]`, with the `M(week, chapter, topic)` helper kept for
a future section created from scratch.

**Wiring new content into a module** (this is the required last step — the student's view is built
from modules, so a homework with no module item is invisible to them):

1. Instructor → Home → the module's ⋮ → **+ Quiz** or **+ Homework** → pick it → Add.
2. Set the due date on the item.

`+ Homework` was added to that menu as part of this week's work; before it, only quizzes could be
attached by hand, and homework items existed solely in seeded courses.
