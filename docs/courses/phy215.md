## Per-assignment notes

### ✅ q1 — "Quiz 1: Welcome & Course Survey"
Four questions, none graded on correctness: three `survey` questions (what interests you / what
can I do to make the course enjoyable / highest math class completed) and one `yesNo` (lab manual
purchased) carrying custom `yesReply`/`noReply` about the bookstore. **Both question types were
added to the engine for this quiz** — before it, a free-response question always went to Claude as
a physics tutor that graded correctness and asked Socratic follow-ups, which is wrong for an
opinion question, and `yesNo` had the textbook-access reply hardcoded.

### ✅ q2 — "Quiz 2: Electric Charge"
Two multiple-choice questions on the two-sphere demo (one negatively charged, one neutral):
before contact → **A, attract** (the charged sphere polarizes the neutral one, and the induced
opposite charge is nearer); after contact → **B, repel** (the conductors share the excess charge,
so both are negative). **The `choices` question type was added to the engine for this quiz** —
graded deterministically, with an authored misconception nudge per wrong option and a retry.

### ✅ q3 — "Quiz 3: Gauss's Law"
Four questions on Ch. 22, **all free response** (the default type — Claude grades the reasoning
conceptually and asks Socratic follow-ups): define Gauss's law, define electric flux, the inflated
vs. deflated balloon around a point charge, and the off-center point charge inside a spherical
Gaussian surface. This is the first PHY 215 quiz to use the default type at all (`q1` is survey +
yesNo, `q2` is multiple choice).

**Why nothing here is a widget.** Questions 3 and 4 each hinge on a yes/no verdict and were the
obvious candidates for `yesNo`, but that type posts a canned reply and never reads the student's
reasoning, which is the entire content of these questions ("Explain your reasoning"). A `choices`
question has the same problem and additionally makes the balloon question a coin flip. Free
response is the right fit: the verdict alone is worth nothing, the justification is the answer.

**Q4 is deliberately labelled (a)/(b)** so `detectParts` (`utils.js`) splits it into two graded
parts. The two halves have *opposite* answers — the field at a point on the surface **does** change
(the charge is now nearer some points and farther from others), while the total flux **does not**
(Gauss's law depends only on the enclosed charge) — and that contrast is exactly what the question
teaches. Splitting means a student who gets one and misses the other keeps the half they earned,
and the multipart grader prompts them by letter for the one still outstanding. The instructor's
source document asks the two as consecutive sentences with no labels; adding them is the only
wording change made to the source.

**Quiz text is plain text, not `MathText`.** Unlike homework prompts, a quiz question renders raw
(`ChatMessages.jsx`, the `msg.type === "question"` branch), so a `$q$` would reach students as
literal dollar signs. Q4 therefore writes the charge as a bare `q`. Keep `$…$` out of quiz text
until that renderer changes.

### ✅ hw1 — "Homework 1: Electric Charge & Electric Field"
10 Y&F Ch. 21 problems (21.2, 21.9, 21.22, 21.30, 21.33, 21.34, 21.45, an instructor-authored
**Clock** problem, 21.73, 21.87) - 35 gradable items. Figures `figE21-30.png` (square of charges) /
`figE21-33.png` (parallel plates) / `figP21-73.png` (ball on a string), copied straight from the
screenshots — figure-only, no caption to crop. The Clock problem is handwritten prose in the
source, retyped as the prompt; its clockface is **rendered by the app** (`VectorField`'s `dial`
backdrop), not a served image.

**21.34 (`hw1_p6a_E2`) exposed a grader bug** (2026-08-10): a student's correct
$-\left(\tfrac35\cdot1.08\times10^4\right)\hat\imath + \left(\tfrac45 1.08\times10^4\right)\hat\jmath$
was marked wrong. MathLive had serialized it as `\frac451.08\times10^4`, which the grader read as
a dropped multiplication sign. Fixed generally by `normalizeLatexForGrading` — nothing about this
problem's content needed changing. Multi-term unit-vector answers built from fractions are the
shape of answer that provokes it, so this set is a good regression test.

**Non-negative parts** (2026-08-10): the magnitudes (`hw1_p3_m`, `hw1_p5a`, `hw1_p5b_y`,
`hw1_p9_m`), the charge/electron amounts (`hw1_p1a`, `hw1_p1b`) and 21.87(c)'s height and
distance (`hw1_p10c_h`, `hw1_p10c_d`) carry `nonNegative: true` in `_answerKeys.js`, so a
negative entry gets a free nudge instead of a wrong verdict. 21.33(b) is the motivating case —
the proton's displacement is *downward*, so a student who computes $-2.72\ \mu\text{m}$ and
types it would otherwise lose an attempt for a convention slip, with the very next part asking
for that direction. Deliberately **not** tagged: 21.45 (`hw1_p7`), whose signed $x$-components
are the physics, and 21.9's sphere charges (`hw1_p2*`) — charge sign is meaningful, and it is
only this problem's stipulation ("given positive charges") that makes them positive.

**Figure sizing** (2026-08-10): all three were rendering at natural size and read too large
beside the prompt, so each carries an explicit `figureWidth` — 21.30 `400` (natural 518×522),
21.33 `400` (506×292), 21.73 `180` (230×498; tall and narrow, so it needs the most reduction).
Setting `figureWidth` on every figure is now part of the authoring procedure
([homework-roadmap.md](../homework-roadmap.md) § Authoring → Figures).

**Parts a plain numeric does not serve, and why:**

- **21.30 is split `vector` + `math`.** The magnitude is an *expression* in $q$ and $a$
  ($\sqrt2 q/\pi\epsilon_0a^2$), so it is `math`; Claude accepts the equivalent $k$-form
  $2\sqrt2 kq/a^2$. The direction is a genuine diagram question, so it is a `vector` part — one
  arrow, direction-only (no `magTol`), `hideTicks`, graded instantly by `gradeVectors`.
- **21.34 is three `math` parts** — the problem explicitly asks for unit-vector form. Verified
  that Claude accepts component reordering and equivalent notation.
- **21.87(a)/(b) are `math`** — symbolic results in $m_p, v_0, \alpha, e, E$. Verified that the
  $2\sin\alpha\cos\alpha$ form of (b) is accepted and that dropping the factor of 2 in (a) is
  correctly rejected.
- **21.87(d) is a `graph`** — "Sketch the trajectory". Key: a concave-up parabola through
  $(0,0) \to (1.4466, -0.4176) \to (2.8931, 0)$, each point verified to lie on the true
  trajectory. Tolerance ±0.080 m, so a flat line (0.418 m off) fails.
- **⚠️ 21.87's parts are reordered** to (a) $h_{max}$ → (b) $d$ → (c) numerical values →
  (d) sketch. The textbook asks for the sketch before the numbers, but `GraphField` needs numeric
  axes, so the student must have the values first. Derive → evaluate → draw. The prompt says so.
- **21.45 uses signed $x$-components rather than magnitude + direction** — every field and force
  in that problem lies on the $x$-axis, so one signed value carries both facts. The stem states
  the convention. Six clean numerics instead of twelve blanks.
- **21.73 opens with an `fbd` part**, then keeps the magnitude + `text` direction split. The
  three forces on the ball are tension along the string, the horizontal electric force, and
  weight; the ball hangs in equilibrium, so `accel: { none: true }`. Tension is the part that needed the
  tolerance to be tight: a straight-up arrow is only 17.4° from the true direction, so the old
  18° default would have accepted it, and "the tension lies along the string" is exactly what the
  problem turns on. It now grades at the standard ±5° like everything else. Being the first tilted force in any FBD, it also surfaced two `FBDField` bugs: the plot was 448×288 px for a 3×3 data range, so a drawn angle was not the graded angle (aiming by eye at 107.4° submitted 101.4°, failing the 5° tolerance), and step 3 of the method hardcoded "every force lies along an axis, so there's nothing to label". The plot is now square and off-axis forces are auto-annotated with their angle to the nearest axis. The FBD also
  feeds `diagramContext` to the grader for the direction part, so a written answer naming $T$ or
  $F$ is read against the student's own diagram.
- **21.22 and 21.73 keep the magnitude + `text` direction split**, since those
  directions need justifying (21.73 especially — the ball's charge is *negative*, so $\vec E$
  points opposite the force, back toward the wall).
- **The Clock problem is a four-part diagram walkthrough**, not one prose blank. The content is
  the pairing/symmetry argument, and a single text box let students assert "3:30" without ever
  doing it, so the reasoning is now drawn:
  (a) `vector` — twelve field vectors on a rendered clockface (`dial` backdrop, `square` plane).
      Each $\vec E_n$ points *away* from numeral $n$, i.e. at numeral $n+6$ — which the prompt
      deliberately does **not** say, since recognizing it is the physics being tested. Graded
      direction-only (`angleTol: 12`, well inside the 30° numeral spacing): grading twelve
      magnitudes would be punishing for no extra insight, and the prompt says nothing about
      magnitude anyway. Instead both vector parts set **`snapMagnitude: true`**, so an arrow
      placed in the right direction is auto-scaled to its correct length at the moment it locks
      green — the student is shown the magnitude relationship rather than tested on it.
      That makes the key lengths a *claim*, so they use `CLOCK_SCALE * n` (exactly proportional,
      since every charge is the same distance from the center): $E_{12}$ is twice $E_6$ and
      twelve times $E_1$. The same scale carries into (b), where each pair's net comes out the
      same length as $E_6$ — the $6q$ result made visible.
  (b) `vector` — the six opposite pairs collapsed to one net field each. The guide names the
      pairs ($12q$ opposite $6q$, …) but *not* the resulting direction: noticing that every
      difference is $6q$ and that each net therefore points at the **smaller** numeral is the
      step being tested.
  (c) `vector` with `render: "axis"` — the dashed axis of symmetry of those six, keyed to
      `clockPoint(3.5, …)` (the 3:30 mark, which is exactly the mean of the six directions) and
      graded `mod180` so the line drawn either way counts. It is aimed rather than placed: the
      line is pinned through the center and rotates with the cursor, and a click anywhere sets
      it. `angleTol: 7` — it has to be under 15° or aiming at the 3 or the 4 would pass, and the
      answer is specifically *halfway between* them.
  (d) `text` — the time plus the justification, which is now a summary of work already done
      rather than the whole problem.
  Key tips are computed from `clockPoint`, the same helper that draws the dial, so they cannot
  drift from what students see. Item ids changed (`hw1_p8` → `hw1_p8a`–`hw1_p8d`), so any draft
  or submission predating this carries the old id.
- **Nothing in this set is ill-conditioned** — no near-zero answers, no hypersensitive roundings,
  so no analogue of PHY 115's 3.54(b).

### ✅ hw2 — "Homework 2: Gauss's Law"
10 Y&F Ch. 22 problems (22.1, 22.3, 22.4, 22.10, 22.14, 22.15, 22.26, 22.42, 22.43, 22.51) —
28 gradable items: 15 numeric, 8 text, 3 math, 1 graph, 1 free-body diagram. One figure (22.43), **drawn for this app
rather than copied from the textbook** — see below. The set is much more conceptual than `hw1`:
two whole problems (22.42, 22.51) contain no numbers at all.

**⚠️ The textbook's Fig. P22.43 is wrong, and is not used.** Y&F draws the positive sphere
deflected *toward* the sheet, i.e. attracted, but the problem states $\sigma = +2.50\times10^{-9}
\text{ C/m}^2$ and the whole solution rests on the sphere being *repelled*. The served figure is
`public/homeworkFigures/physics2/HW2/figP22-43.png`, drawn for this purpose with the sphere pushed
**away** from the sheet, the sheet's positive charge marked with $+$ signs, and $\theta$ measured
from a dashed vertical. Its source (`figP22-43.source.html`, an inline SVG) sits beside the PNG so
the figure can be re-rendered or edited; regenerate with headless Chrome at
`--force-device-scale-factor=2` (natural size 920×1080, served at `figureWidth: 260`). The drawn
angle is a schematic ~30°, deliberately not the 10.2° answer. This is the first app-authored
figure in either course; every other figure is a textbook screenshot.

**Parts a plain numeric does not serve, and why:**

- **22.42 is entirely symbolic: two `math` parts, one `text`, one `graph`.** (a) $\rho r/2\epsilon_0$
  and (b) $\lambda/2\pi\epsilon_0 r$ are expressions, (c) is the comparison at $r = R$ (the content
  is the substitution $\lambda = \rho\pi R^2$ and what continuity at the surface means), and
  (d) "Graph the electric-field magnitude" is a sketch. There is no numeric part in this problem.
- **22.42(d) uses normalized axes**, $r$ in units of $R$ and $E$ in units of the surface value
  $\rho R/2\epsilon_0$, because `GraphField` needs numeric axes and the problem supplies no numbers.
  The prompt states the scaling. Two curves: `inside` (straight, origin to $(1,1)$) and `outside`
  (`curveUp` through $(1,1), (1.5, 0.667), (2, 0.5), (3, 0.333)$), `yTolFrac: 0.08`. That tolerance
  was chosen against the grader's piecewise-linear interpolation: a student who anchors the outside
  curve at only $r = R, 2R, 3R$ interpolates to 0.75 at $1.5R$ against a key of 0.667, which passes,
  while a straight-line outside curve (0.833 there) fails. Verified against eight sketches: the two
  honest ones pass and all six wrong ones (straight decay, too-fast decay, constant field inside,
  curved inside, stopping at $2R$, field rising outside) fail.
- **22.51 is `math` + two `text` parts.** "Calculate the force (magnitude and direction)" splits
  into the expression $qQ/4\pi\epsilon_0r^2$ and the direction, which needs justifying (it is
  attractive, and the shell acts exactly like a point charge at its center). Part (b) is one `text`
  part rather than a numeric zero, because the Gaussian-surface argument *is* the answer.
- **22.10 is deliberately signed, and (a) is exactly zero.** The three radii enclose neither
  charge, then $q_2$ only, then both, so the sign of each flux is the physics; these are the only
  numeric items in the set without `nonNegative`. `matchValue` special-cases a zero answer
  (accepts $|s| \le$ tol), and this zero is exact — nothing is enclosed — not a near-cancellation,
  so it is not ill-conditioned. Same for 22.14(b), $E = 0$ inside a conductor.
- **22.1(b)/(c) and 22.14(c) are `text`.** 22.1(c)'s answers are $0°$ and $90°$, but "Explain your
  answers" is the question; splitting it into two angle numerics would grade the trivial half and
  drop the real one.
- **Three conceptual `text` parts were added beyond the textbook's wording** — 22.4(d) (why the
  radius change leaves the flux alone but the length change does not), 22.14(c) (justify $E = 0$
  inside with Gauss's law) and 22.43(b) (why the angle is independent of distance and thread
  length). Each states reasoning the instructor's own key writes out in the margin, so the app
  grades what the key already treats as part of the answer.
- **22.4(b) is a numeric equal to (a).** That the number does not move is the point of the part;
  the added (d) is where the student has to say why.
- **22.43 opens with an `fbd` part whose angle is symbolic.** It is the direct analogue of 21.73
  (tension along a string, a horizontal electric force, weight, equilibrium), but with one
  difference that drove a small engine change: 21.73 *states* the string angle, while here the
  angle **is** what part (b) asks for. `FBDField` normally annotates each off-axis force with its
  measured angle to the nearest axis, which would have printed "10°" on the diagram before the
  student solved for anything. The fix is `angleSymbol: "θ"` on the `fbd` config, which labels the
  arc with the name instead of the number (see [../homework-roadmap.md](../homework-roadmap.md)
  § 6c). So the part can be asked in the order the lecture method teaches: draw the diagram, mark
  the unknown angle, then solve for it.
  - **The tension is graded at ±22°, not the house ±5°**, keyed at the figure's schematic 25° from
    vertical. At FBD time the given data have not fixed this angle, so a tight window would grade
    an answer the student cannot yet have. The band (roughly 4° to 47° from vertical) enforces
    exactly what the FBD *does* establish: the tension leans back along the thread, toward the
    sheet. A straight-up tension is rejected, and that is the real misconception, since with no
    horizontal component nothing balances the electric force. The other two forces stay at ±5°,
    being axis-aligned.
  - `angleSymbol` on that force also keeps `snapFBDDirections` off it, so the arrow stays where the
    student drew it. Snapping it onto the key would assert a precision the physics has not fixed,
    and a near-vertical snapped arrow would hint that θ is small. `F` and `w` still snap to their
    exact axes.
  - The prompt adds one sentence orienting the student ("the sheet is on the left and the sphere
    hangs to the right of the vertical") so the FBD's left/right sense is unambiguous, and the
    reveal diagram is also labelled θ, so even "Show answer" on part (a) does not leak part (b).
- **Nothing in this set is ill-conditioned.** The two zeros are exact, and every other value is a
  clean product or quotient of the given data.

**Non-negative / angle tagging:** the flux and field magnitudes (`hw2_p1a`, `hw2_p2a`, `hw2_p3a-c`,
`hw2_p5a`, `hw2_p5b`), the charge (`hw2_p2b`), the force (`hw2_p6`), the work (`hw2_p7a`) and the
speed (`hw2_p7b`) carry `nonNegative: true`. 22.26(a) is the motivating case here: the electron is
negative and the sheet positive, so a student who tracks the signs through $W = qE\,\Delta x$ can
easily land on $-6.56\times10^{-21}\text{ J}$ for what is genuinely positive work, and gets a free
nudge rather than a lost attempt. `hw2_p9a` (the thread angle) is tagged `angle: true` instead.
The three 22.10 fluxes are tagged with neither, since their signs are the answer.

**Scientific notation:** `sci: true` on the flux answers (22.3(a), 22.4(a)-(c)), the work
(22.26(a)) and the speed (22.26(b)), so the reveal reads "3.53 × 10⁵ N·m²/C" rather than "353000".
22.3(b) is expressed in μC and 22.15 in newtons instead, keeping those reveals free of exponents.

**Wording changed from the source (one place only):** 22.3(a) asks for the **magnitude** of the
flux. The textbook says "What is the electric flux", but it only ever gives the field's magnitude,
so the sign of the charge (and therefore of the flux) is genuinely indeterminate from the problem
statement; part (b) already asks for the magnitude of the charge, so this makes the two consistent.

**Scientific notation.** This is the first set whose answers are mostly exponential, which
exposed that `toSigFigString` deliberately never emits sci-notation — 1.25×10¹⁹ rendered as

## Modules — hand-built, so `MODULES_PHYSICS2` stays empty

The live PHY 215 class's 17 modules were built **by hand** in the instructor Modules editor. The
seed template is only copied into a class's RTDB `modules` node when that node is **absent**
(`App.jsx` ~line 396), so for this class the template can never apply. Populating
`MODULES_PHYSICS2` would therefore have no effect while silently diverging from what students
actually see — so it is deliberately left `[]`, with the `M(week, chapter, topic)` helper kept for
a future section created from scratch.

**Wiring new content into a module** (this is the required last step — the student's view is built
from modules, so a homework with no module item is invisible to them):

1. Instructor → Home → the module's ⋮ → **+ Quiz** or **+ Homework** → pick it → Add.
2. Set the due date on the item.

`+ Homework` was added to that menu as part of this week's work; before it, only quizzes could be
attached by hand, and homework items existed solely in seeded courses.

**Previewing what you attached:** click the item's **title** in the Modules editor and it opens the
real student screen in preview mode (badged "Preview", nothing saved, "← Back" returns to Modules).
That works for quizzes and homework alike, and is the intended way to proof newly authored content
such as `q3` before students see it. Homework preview writes no draft and no attempt counts, so you
can run the same set as many times as you like.
